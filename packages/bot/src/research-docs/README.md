# Shared research documents
Independent research-docs/v1 resource plane. New App identity, capability object, permission digest, shared membership and CRDT directory; research-v2 storage is never rewritten. The library is server-owned Yjs metadata. Page contents use the existing append/fsync/apply CRDT store and never enter App State. Page IDs and file names are server-generated hashes. Each call revalidates the current binding, membership and grant after awaits. Source calls enter the original research-v2 resource plane as the same actor and require its independent membership/grants.

The BlockNote seed encoder only writes the reviewed subset needed for templates and imports; a schema compatibility browser test must accompany changes. Rich editor updates are opaque Yjs state within page quotas. Comments carry server-bound authors separately from editable page content. Presence is derived from live opened instances, not fake collaborator data. Revocation drops open watches and prevents subsequent reads/writes.

Pages have no size ceiling (2026-10-20). `read` and `update` carry an optional `offset`: a read answers one 192 KiB window of a per-instance snapshot (`snapshot` + `next` continue it, so windows never mix versions), and a push sends 192 KiB parts with `offset`/`total` that are staged per instance and document and merged once through the store's validate/append/apply order. Staging is dropped on gaps, after ten idle minutes, beyond eight documents per instance, and when the instance closes or its owner is revoked. Calls without an offset keep the old single answer and refuse past the old 2 MiB page size with a request to refresh. Neither the library nor a discussion has a count or size ceiling either (2026-10-20). The library CRDT holds only the page directory and create requests; each page's discussion is its own CRDT (`documents/comments`, keyed like the page). Calls read both in place through `CrdtDocumentStore.inspect` (a directory lookup is O(1); a list page sorts the live entries, it never decodes or encodes the CRDT); writes still copy the one document they change and merge the difference through validate/append/apply, so a create or rename costs O(directory) and a comment O(that page's discussion). `library` and `comments` with `limit` (at most 200) or `after` answer one page in creation order, cut at about 192 KiB of JSON, with `next` (the last entry's id; entries are never deleted, so the cursor stays valid). Without either they answer the whole list for an older View, refused past the old 4 MiB library bound with a request to refresh. Discussions written before this lived in the library: the first access of a space copies them by id into the page stores and only then removes them from the library, so the move is idempotent across crashes and loses nothing. An older Head run against migrated data shows those discussions as empty (they remain on disk) and anything it adds moves over at the next access here.
