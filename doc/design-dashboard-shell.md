## 现状

`page.ts`(登录页 + 总览)与 `sessions-page.ts` 各自内联一整块 `<style>`,
基础样式(字体、色板、按钮、卡片)重复且已经开始漂移;页面之间没有任何
导航——互达只能手改 URL。

## 方案:一个壳,页面只出内容

新增 `dashboard/shell.ts`,导出 `renderShell({ active, title, content, identity })`:

- **共享设计令牌**:`:root` CSS 变量(色板、字号阶梯、间距、圆角、代码字体、
  状态色 success/warn/error)。以 sessions 页现有视觉为基准提取(它最新、
  打磨最多),总览页向它靠拢,而不是再发明第三种;
- **顶部导航条**:`总览 | 会话 | 开发`,当前页高亮;右侧**身份 chip**
  (用户名,管理密钥显示「管理」)带下拉:登出、复制本人登录链接(换设备用);
- 移动端:导航横向滚动即可,页面只有三个,不做汉堡菜单;
- 登录页不套壳(无身份、无导航);
- 各页面改造为**内容渲染器**:删除各自重复的基础样式,只保留页面特有部分
  (sessions 的树/气泡、总览的表格)。页面自己的 JS 不动。

## 跳转交互

| 从 → 到 | 交互 |
|---------|------|
| 总览 → 会话 | 每个用户/设备行尾「查看会话」,直达 sessions 页并选中该设备 |
| 会话 → 工单 | session 若关联 dev ticket(session_id 反查),会话头部显示「所属工单 #n」链接 |
| 工单 → 会话 | 工单页右侧本就是内嵌会话视图;另给「在会话浏览器打开」跳原生页(要完整侧栏/搜索时用) |
| 工单 → 部署 | 工单页顶部计数器(「已开发未上线 N / 已上线未验证 M」)点开部署面板 |
| 任意页 | 导航条常驻,一次点击互达 |

## 实施顺序与测试

1. 抽 `shell.ts` + 设计令牌,总览/会话两页接入——**纯重构,不改任何功能**,
   单独一个 commit 方便回归;
2. 工单页从第一天起长在壳里。

测试:壳渲染纯函数单测(active 高亮、身份 chip 内容、HTML escape);
总览/会话两页的现有测试作为回归网。
