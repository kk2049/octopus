# Fieldnote 科研项目工作台：C0 设计说明

## 结果

原型把“资助科研项目”作为唯一顶层导航和授权心智模型。进入项目后，用户首先得到一组并列且始终可追溯的当前主导对象：最新主导 agent 会话与最相关的状态文档。成员管理、主导绑定和内容阅读是三个不同动作，不共享模糊的“管理”入口。

本原型仅含虚构数据，不连接服务、不读取文件、不发送邀请，也不模拟持久化成功。

## 信息层级与主流程

1. 左栏按项目组合列出资助项目；项目行同时给出健康信号、主导 agent 摘要和未读数。
2. 进入项目后先看项目身份与授权范围，再看当前主导 agent 和当前主导文档。
3. 主区并排呈现最新会话与现状汇报。会话中的文件意图以明确文件卡出现，可定位到报告小节，但原型不打开真实文件。
4. 负责人可切换主导 agent、主导文档，查看绑定历史，并邀请项目成员。协作者只能使用内容工作区；只读访客只见允许的状态内容。
5. 每次绑定保留旧引用和操作者/时间/原因，当前值只在可信结果到达后变化。处理中禁止重复提交；拒绝时保留所选值与说明。

## 关键交互判断

- “默认打开最新 chat”和“默认打开最对的文档”被解释为两个显式、可独立变更的主导绑定；系统可以建议，但不能静默替换。
- agent 可以通过项目范围工具提议主导变更；人的项目负责人仍可确认或直接变更。agent 不能表达自己的身份、权限或项目成员关系。
- 工作目录、agent 和工具挂载是授权实现，不作为普通文件树暴露；界面只解释项目范围与结果状态。
- 历史记录是只读时间线，避免把旧主导会话误认为已删除。
- 邀请类似代码托管平台的成员模型：项目内角色、等待接受、可见范围说明；不默认继承其它项目的成员资格。

## 状态与角色覆盖

- 正常/密集：三个活跃项目、一个归档项目、长会话、两张文件意图卡、状态报告、历史与成员列表。
- 首次使用：缺少主导绑定时给出顺序明确的第一步，不制造空仪表盘。
- 处理中：保持旧主导值，禁用重复提交，显示非权威的等待状态。
- 被拒绝：说明可恢复原因，保留表单输入并给出重试入口。
- 结项/只读：内容仍可追溯，所有绑定与成员动作隐藏或禁用。
- 角色：负责人有管理动作；协作者保留项目工作区但没有成员/绑定管理；访客为只读。

## 响应式与可访问性

- 宽屏是 286px 项目栏、主会话和状态报告双栏；在 900px 下项目栏变成横向项目带，内容改为单栏；390px 下操作按钮和指标继续纵向重排。
- 使用原生按钮、表单、tab 角色与 dialog；所有图标按钮有可访问名称，键盘焦点使用高对比描边。
- 会话和文档都有独立滚动边界；窄屏取消内部固定高度，避免嵌套滚动陷阱。
- 角色隐藏只用于原型表达。真实隐私边界必须首先来自面向当前查看者的数据裁剪，而非 CSS。

## 刻意不做

- 不设计通用文件导航栏；文档通过当前状态入口或会话意图打开。
- 不在 C0 中定义后端 action 名、传输协议、框架组件或模块拆分。
- 不模拟真实身份、批准、邀请接受、文件挂载或 agent 运行。
- 不提供删除项目、删除历史或强制解除挂载等不可逆动作。
- 不把自动选出的“最对文档”当作权威写入；自动化仅能形成候选或提议。

## C0 评审

- 主要角色、决定与下一步无需说明即可识别：通过。
- 负责人、协作者和访客不是仅靠隐藏同一仪表盘按钮区分：通过；其可见动作及项目元信息不同，真实实现仍须做投影裁剪。
- 处理中、拒绝和结项状态已有明确行为：通过。
- 390px 窄屏与键盘焦点有明确实现：通过。
- 不暗示尚不存在的授权或数据访问：通过；原型横条和提交反馈持续标明不持久化。
- DOM 与信息层级围绕科研项目、主导对象和进展阅读，而非通用卡片集合：通过。

C0 结论：通过，可以进入契约映射与集成。

## 已自行收敛的产品决策

- 初版每个项目仅有一个当前主导 agent 和一个当前主导文档；历史可以无限保留，UI 分页属于后续容量工作。
- 初版角色固定为 Owner、Member、Viewer；自定义角色和细粒度文件 ACL 不进入本次范围。
- 邀请先生成待接受成员资格，不自动授予其它项目，也不把外部邮箱暴露给非 Owner。
- agent 发起的绑定变化采用“提议”语义；是否需要人类批准由可信策略决定，UI 不自称批准已经发生。
