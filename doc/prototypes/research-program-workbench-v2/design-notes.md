# 自主科研工作台 v2：交互说明

## 结果

自主科研不再以“先选一个带内部标识的实例，再进入 App”为入口。用户从一级卡片进入后立即落在一个项目工作台；项目列表、分享、加入和成员管理都属于同一个窗口的导航层。

## 层级与关键决定

- 全局面板只需要一个“自主科研”一级卡片，与开发、会话等入口平级；实例不是全局卡片。
- App 左侧栏是项目切换器。当前项目使用人类可读名称，内部实例标识不进入主视觉层。
- 工作区首屏并列展示最新会话和当前主导文档，回答“现在发生什么”和“现状结论是什么”。
- 项目列表可以折叠，但折叠不改变当前项目。窄屏使用抽屉，选中项目后收起。
- 分享链接、成员头像和邀请入口紧贴项目列表。邀请以当前工作台上的 modal 完成，不跳到中间页。
- 空项目仍进入工作台，解释下一步；归档项目进入只读工作台，不伪装可写权限。
- 复制与邀请需要 pending、成功和拒绝反馈；pending 时阻止重复提交，拒绝时保留当前浏览上下文。

## Actor 差异

- Owner：可以看到成员与邀请、分享、新建和项目管理动作。
- Member：可以切换项目、分享已有邀请链接并参与项目工作，但不获得 Owner 管理能力。
- Viewer：进入相同工作台阅读内容；成员管理入口替换为成员摘要，写动作不出现。
- 未加入用户：通过项目 URL 到达同一壳层内的加入状态，而不是单独实例跳转页；加入后原地显示工作台。

## 响应式与可访问性

- 宽屏保持 284px 项目导航和双栏工作区。
- 860px 以下导航变成显式菜单抽屉，工作区单列。
- 导航、项目、邀请和关闭均为原生 button；焦点态可见，modal 带 dialog 语义与状态反馈区域。
- 标题和状态不依赖颜色表达；项目折叠使用 `aria-expanded`。

## 有意省略

- 原型不模拟真实身份、邀请落库、链接复制权限或 Agent 接入成功。
- 原型不展示内部实例 id、token、真实路径或真实项目数据。
- 原型不决定全局面板的具体实现组件，只规定一级信息架构和落点。

## C0 评审

通过。首要角色、当前项目、最新工作与下一动作无需解释即可识别；Owner、Viewer、未加入用户的入口不同；空、正常、pending、拒绝、归档和窄屏状态均有落点；界面不暗示 View 自身拥有成员权限。没有需要用户决策的未决产品问题。
